# CRISPR-Sim PostgreSQL Database

## Why PostgreSQL (not MongoDB)

| Need | PostgreSQL | MongoDB |
|------|------------|---------|
| Users + JWT sessions | Strong relational FKs | Possible but weaker fit |
| Simulation history (sessions → scans → repairs) | Natural 1:N schema | Embedded docs get messy |
| Literature / gene reference data | JSONB + SQL queries | Good, but less join-friendly |
| Render hosting | Native Render Postgres | Extra Atlas setup |
| ACID for audit logs | Yes | Eventual consistency trade-offs |

**Recommendation:** PostgreSQL for this app.

## Schema

```
users                 — accounts (email, bcrypt hash)
revoked_tokens        — JWT logout blocklist
sequence_sessions     — each DNA input workflow
pam_scans               — PAM scan results per session
simulations           — NHEJ/HDR + analysis outcomes
genes                 — HBB, TP53, BRCA1 reference cards
literature_cases      — published validation benchmarks
research_papers       — PubMed-cited CRISPR studies
audit_logs            — login, sequence, security events
```

## Docker (local)

```powershell
cd d:\Crispr\crispr_sim\backend
docker compose up --build
```

- API: http://localhost:8000
- Postgres: `localhost:5432` (user `crispr`, password `crispr_secret`, db `crispr_sim`)

## Render (production)

1. Deploy [crispr-sim-backend](https://github.com/vskanna0510/crispr-sim-backend) with `render.yaml` (includes free Postgres).
2. Set `JWT_SECRET` (auto-generated by Blueprint).
3. URL: https://crispr-sim-backend.onrender.com

## Flutter APK

```powershell
flutter build apk --release --dart-define=API_BASE_URL=https://crispr-sim-backend.onrender.com
```

Users must **register / sign in** before running simulations (when `REQUIRE_AUTH=true`).
